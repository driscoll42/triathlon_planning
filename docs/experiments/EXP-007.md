# `EXP-007`: Multi-Distance Season Validation on CURRENT_ATHLETE and an Unconstrained Reference Profile

## 1. Objective & Pre-Registered Hypothesis
- **Objective:** Run sprint / olympic / 70.3 / Ironman seasons on `CURRENT_ATHLETE` (45-75 min/day, one session/day, no pool, 24-week re-entry) and on an unconstrained reference profile (up to 300/240 min Sat/Sun, 120 min weekdays, two session windows, pool every day, no re-entry, CTL 45) and check Tier-0 caps with a checker that re-computes every quantity from the solved schedules.
- **Null Hypothesis ($H_0$):** At least one solved week violates a Tier-0 cap, or a week falls back / degrades silently.
- **Alternative Hypothesis ($H_1$):** 0 fallback weeks, 0 violations, and every time-budget shortfall is named in an explicit season-level diagnosis.

## 2. Pre-Flight Ceteris-Paribus Hygiene Checklist
- [x] **Environment Quiescence:** one matrix run alone on the machine (8 processes, 3.5 s/week solver limit).
- [x] **Cold vs. Warm State Control:** each season in its own process; deterministic single solve per week (`ADR-018`).
- [ ] **Sample Size:** n = 1 per cell (a season is 12-48 sequential solves); wall times are indicative only.

## 3. Non-Goals & Safety Bounds
- **DO NOT** loosen any guardrail. The reference profile changes only the time budget, facilities, session windows and starting state; axial / neuro / run-share / 48h / 80/20 limits are the engine defaults and profile values.
- ODI, raw running ACWR, durability and load-model calibration are owned by `TASK-022`, `TASK-023`, `TASK-021` and are reported, not fixed.

## 4. Control vs. Treatment Matrix & Test Corpus
- **Workload:** `python -m triplan.perf.season_validation --report <file>`; `src/triplan/perf/season_validation.py` (`check_season`, `run_matrix`). Race block = `DEFAULT_RACE_WEEKS` (12/16/20/24); `CURRENT_ATHLETE` adds its 24 re-entry weeks. Reference base weekly TSS 250/330/400/450.
- **Checker (independent of the solver report):** rolling 48h TSS / ANS / mech strain incl. the Sunday->Monday boundary, daily/weekly axial and neuro, single-run share by running minutes (pigeonhole caps for < 4 runs), deadlift <-> heavy/long-run lockout (same day and +-24h), no back-to-back hard days, one lift/day, daily and weekday-single time caps, 80/20 low >= 78% and Z3+ZY+Z4+Z5 <= 20%, in-model running ACWR row, CTL ramp, run-minutes guard, fallback / empty weeks.

## 5. Telemetry Instruments & Sampling Commands
- Max 48h loads, max daily axial / neuro, max single-run share, minimum weekly low-zone share and maximum weekly high-zone share, relaxation count, wall time per season; plus ODI, raw ACWR and solved/target TSS by week role.

## 6. Pre-Registered Go/No-Go Decision Rule
Adopt the validation module as the regression gate **ONLY IF** all 8 seasons show 0 fallback weeks and 0 violations, and the `CURRENT_ATHLETE` Ironman / 70.3 seasons carry an explicit time-budget infeasibility message. Otherwise record `COMPLETE_NULL_REJECTED` and open fix tasks.

## 8. Architectural Conclusion & Action Taken
- **Verdict (H1 holds):** 0 fallback weeks and 0 independent Tier-0 violations in all 8 seasons (36 / 40 / 44 / 48 weeks for `CURRENT_ATHLETE`; 12 / 16 / 20 / 24 for the reference).
- **Explicit infeasibility diagnosis:** `control/feasibility.py` adds a season-level report (`summary.attrs["infeasibility"]`, printed after the season): `CURRENT_ATHLETE` gets "Olympic long ride 90+ min cannot fit 45-75 min/day caps", "70.3 long ride 150+ / long run 90+ ...", "IM long ride 180+ min cannot fit 45-75 min/day caps ... IM peak week needs ~13 h but the time budget allows at most 5.8 h/week", plus every named relaxation rolled up by week range (the 180 min ride and 75 min run anchors are dropped in every week). The reference profile reports the library gap instead: no run >= 90 min exists for 70.3 / IM.
- **Observations (owned elsewhere):** ODI peaks 4.1-5.9 (current) / 1.9-2.6 (reference) (`TASK-022`); raw running ACWR 1.76-1.95 (current, re-entry) / 1.26-1.40 (reference) while the in-model row holds (`TASK-023`).
- **New defects found (queued):** `TASK-037` (build-week TSS floor above low targets: median solved/target 1.3 for `CURRENT_ATHLETE`), `TASK-038` (recovery/taper/race overshoot up to +68 TSS current, +244..+275 reference), `TASK-039` (`CURRENT_ATHLETE` solves with < 4 runs in every week and a single run in 13-25 weeks per season, so the 32% single-run cap is vacuous there), `TASK-040` (long-course library gaps and non-configurable 48h TSS / strain caps; the reference 70.3 / Ironman build weeks undershoot by up to 87 / 183 TSS with the 48h TSS cap at 289-294 of 295).
- **Production Action:** `perf/season_validation.py`, `control/feasibility.py`, `WeekRecord` collection hook in `generate_closed_loop_season_schedule`, `tests/test_season_validation.py` (17 fast tests + 8 `slow` full-season tests, `-m slow`).

Findings:
- **The library gap is closed, the Ironman targets are not reachable under the charter caps.** The season diagnosis no longer says "no run >= 90 min in the workout library"; it now reports `Rolling 48h ANS cost cap 700 binds in 4 of the 4 short week(s) (14-15,18-19; peak 690)`. The charter caps (295 / 260 / 700) were not raised anywhere (reference keeps them).
- **70.3 build weeks are within 10% of target** (worst -41 of 613, -6.7%); Ironman build weeks 14 / 15 / 18 / 19 are -10% / -13% / -12% / -20% (`TASK-050`).
- **Long rides appear in the reference recovery / taper weeks only** (210-300 min, anchors optional there); in build weeks the mandatory 180 min anchor plus a 165 min ride already fill the weekend pair at 260 of the 295 TSS and 640 of the 700 ANS 48h cap. Reference recovery undershoot (-157 / -186 / -225 TSS) became -18 / -2 / -41 (a side effect of the longer rides giving the solver TSS density).
- **Long runs are still never chosen** by the reference: it sits in permanent re-entry (run CTL 10-11 < exit 15, long run <= 45, +15 min/week), so runs stay 33-60 min (`TASK-049`).
