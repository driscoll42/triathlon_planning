# `EXP-009`: Include 80/20 Endurance Library Options in Default and Hybrid MILP Pools

## 1. Objective & Pre-Registered Hypothesis
- **Objective:** Expose the 479 `8020_library` workouts (derived from `data/Run.xlsx`, `data/Bike.xlsx`, `data/Swim.xlsx`) in `build_default_candidate_library()` and `build_hybrid_candidate_library()` by default without exploding MILP solve time (`TASK-060`) or breaking Tier-0 invariants across all 8 validation seasons.
- **Null Hypothesis ($H_0$):** Adding `8020_library` options breaks 8-season validation (fallback weeks, Tier-0 violations, or duplicate keystone anchors) or makes weekly MILP solves time out without incumbents.
- **Alternative Hypothesis ($H_1$):** With sparse run-share constraints, Phase-B MIP start, lossless athlete-feasibility pre-filtering, stratified `8020_library` representative pruning (`easy <= 6`, `tempo <= 4`, `hi <= 4` per sport), and canonical keystone selection, all 8 seasons solve with 0 fallback weeks and 0 Tier-0 violations, and plans organically select `8020_library` workouts.

## 2. Pre-Flight Ceteris-Paribus Hygiene Checklist
- [x] **Environment Quiescence:** Full 8-season matrix ran in 8 parallel processes (`time_limit=3.5s/week`).
- [x] **Cold vs. Warm State Control:** Deterministic single solve per week (`ADR-018`); control baseline is `EXP-008` (`52` `lib_default` rows on `fe614a7`).
- [x] **Sample Size & Rigor:** Single-week matrix/solver diagnostic plus full 8-season matrix (`4` distances × `2` profiles = 240 total weeks) and 20-week hybrid plan generation.

## 3. Non-Goals & Safety Bounds
- **DO NOT** loosen any Tier-0 guardrail or alter `lib_default` / `lib_hybrid` CSV flags (`refresh_from_8020_scrape` stays idempotent).
- **DO NOT** force `8020_library` picks via constraints; they enter as optional candidates alongside the curated core.

## 4. Control vs. Treatment Matrix & Test Corpus
- **Workload / Dataset:** `python -m triplan.perf.season_validation` (`sprint`, `olympic`, `70.3`, `ironman` × `current`, `reference`) + `scripts/generate_level0_hybrid_20w.py` (20-week duathlon + strength plan).
- **Condition 1 (Control Baseline):** `EXP-008` (`52` `lib_default` rows only; `8020_library` excluded).
- **Condition 2 (Treatment A):** `build_default_candidate_library()` / `build_hybrid_candidate_library()` with `include_8020=True` (`531` / `501` candidates) + lossless feasibility pre-filter + stratified `8020_library` pruning (`<= 14` per sport) + sparse `r_tot` run-share constraint + Phase-B MIP start + canonical keystone run selection.

## 8. Architectural Conclusion & Action Taken
- **Verdict:** **H1 holds (`COMPLETE_ADOPTED`)** — 0 fallback weeks and 0 violations across all 240 season-validation weeks; `reference` seasons run equal-to-30% faster with fewer relaxations, while `current` seasons use ~2.5x wall time (within budget) and reduce 70.3/Ironman relaxations (`73->62`, `84->67`).
- **Key Findings:**
  1. Unfiltered `8020_library` (`N=500`) blew up `_add_run_share_cap` to $O(R^2)$ nonzeros (~4.6M nnz) and timed out before finding an incumbent. Introducing continuous `r_tot` reduced nonzeros by 5x–30x with identical LP relaxation.
  2. Passing Phase-A's solution as a MIP start (`h.setSolution`) to Phase B prevents `TIME_LIMIT_NO_SOLUTION` fallbacks to unoptimized Phase-A schedules.
  3. Filtering unhostable non-anchor/non-test rows and stratifying `8020_library` by `(sport, easy|tempo|hi)` across feasible durations keeps the solver compact while preserving full 80/20 variety.
  4. `apply_keystone_week` needed canonical keystone codes (`RUN_AE2_LONG`, `RUN_LC_Z2_*`) so `8020_library` runs sharing durations `75/90/105/120/150` (`RF12`, `RAe3`, etc.) are not marked as duplicate mandatory anchors.
- **Production Action:** Recorded as `ADR-029`; updated `model/candidates.py`, `library/{loader,candidates}.py`, `solver/{pruning,safety_constraints}.py`, `solver/engine/{config,engine}.py`, `control/periodization.py`, `scripts/generate_level0_hybrid_20w.py`, and regenerated `training_plans/level0_hybrid_20w_{daily,summary}.csv`.
