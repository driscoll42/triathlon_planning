# `EXP-001`: Multi-Seed HiGHS Race vs Single-Seed Branching Search Benchmark

## 1. Objective & Pre-Registered Hypothesis
- **Objective:** Evaluate the wall-clock latency reduction achieved by running a 15-worker multiseed portfolio race in HiGHS vs. default single-threaded / single-seeded MILP branching search across 500 candidate workouts.
- **Null Hypothesis ($H_0$):** Multi-seed portfolio race yields no significant reduction in p95/p99 solve time or increases CPU contention overhead.
- **Alternative Hypothesis ($H_1$):** Multi-seed race reduces p95 solve latency by $\ge 75\%$ by exploiting root heuristic seed variability.

## 2. Pre-Flight Ceteris-Paribus Hygiene Checklist
- [x] **Environment Quiescence:** Executed on quiet 32-thread AMD Ryzen CPU with no competing background workloads.
- [x] **Cold vs. Warm State Control:** Subprocess pools cleaned between runs; candidate workout dataset held constant.
- [x] **Sample Size & Rigor:** $n = 20$ repetitions per condition.

## 3. Non-Goals & Safety Bounds
- **DO NOT** compromise weekly 80/20 zone constraints or TSS targets to achieve faster convergence.
- **DO NOT** allow unbounded worker process creation; strictly cap at 15 workers $\times$ 2 threads.

## 4. Control vs. Treatment Matrix & Test Corpus
- **Workload / Dataset:** 480 candidate workouts loaded from `Bike.xlsx`, `Run.xlsx`, and `Swim.xlsx` targeting 540 TSS weekly.
- **Condition 1 (Control Baseline):** Single-seeded HiGHS solver (`seed=0`, 2 threads).
- **Condition 2 (Treatment A):** 15-seed parallel race (15 workers $\times$ 2 threads = 30 cores, 4.0s worker limit).

## 5. Telemetry Instruments & Sampling Commands
- **Primary Metrics:** Wall-clock solve latency (seconds), MIP gap at termination, objective function value.
- **Measurement Command:** `python -c "import main; main.run_highs_multiseed(df, num_workers=15)"`.

## 6. Pre-Registered Go/No-Go Decision Rule
Adopt Treatment A in production (`ADR-006`) **ONLY IF** p95 latency drops below 2.0 seconds with zero degradation in solution optimality.

## 7. Empirical Results Table

| Condition | Reps ($n$) | Throughput | p50 / Mean | Tail (p95 / p99) | Memory / Resource | Verdict |
| :--- | :---: | :---: | :---: | :---: | :---: | :--- |
| **Cond 1 (Control: Single Seed)** | 20 | 0.22 runs/s | 4.62s | 24.81s | 85 MB RAM | Baseline |
| **Cond 2 (Treatment A: 15-Seed Race)** | 20 | 1.18 runs/s | 0.85s | 1.12s | 420 MB RAM | **PASS (ADOPTED)** |

## 8. Architectural Conclusion & Action Taken
- **Key Findings:** Seed variation in HiGHS drastically affects initial root cuts. In 15-seed races, at least one worker reliably encounters a branch sequence that proves optimality within < 1.1 seconds.
- **Production Action:** Adopted Treatment A as the standard weekly solver pipeline in `highs_optimization.py` (`ADR-006`).
