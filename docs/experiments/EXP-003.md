# `EXP-003`: Solver Correctness, Sparse Build and Dominance Pruning Scaling Benchmark

> **Status:** `QUEUED` (`QUEUED_SPEC`) — **Run First in P2.** Formally retests `EXP-001` (`NEEDS_RETEST`) and validates `ADR-017` (sparse CSR `WeekModel`) and `ADR-018` (single deterministic solve + dominance pruning + selection Top-K cuts).

## 1. Objective & Pre-Registered Hypothesis
- **Objective:** Quantify how model build time, HiGHS solve latency, and proven MIP optimality gap scale with candidate pool size ($N \in \{40, 80, 160, 324, 500\}$) on the unified `WeekModel` engine (`src/triplan/solver/engine/model.py`), verify that Top-5 selection-cut plans (`ADR-018`) produce strictly monotone non-improving objectives, and retest `EXP-001` by comparing a 15-seed $\times$ 2-thread parallel race against a single deterministic solve at equal CPU/wall-clock budget.
- **Null Hypothesis ($H_0$):** Single deterministic solves with dominance/representative pruning (`src/triplan/solver/pruning.py`) fail to reach $\le 1.0\%$ MIP gap within $\text{p95} \le 2.0\text{s}$ at $N \le 120$, or the 15-seed portfolio race achieves strictly better proven MIP gaps at equal CPU budget.
- **Alternative Hypothesis ($H_1$):** With sparse CSR row construction (`WeekModel.add_row` / `addRows`) and pre-solve pruning (`N <= 120` per `TASK-060`), a single deterministic solve reaches $\le 1.0\%$ relative MIP gap with $\text{p95} \le 2.0\text{s}$, returns strictly monotone Top-5 objective values under `cut_mode="selection"`, and matches or beats the 15-seed race without multiprocessing overhead.

## 2. Pre-Flight Ceteris-Paribus Hygiene Checklist
- [ ] **Environment Quiescence:** Execute on quiescent 32-thread AMD Ryzen machine with no competing solver or test processes.
- [ ] **Cold vs. Warm State Control:** Enforce a single process-wide HiGHS thread setting (`src/triplan/solver/highs_runtime.py`); construct a fresh `WeekModel` / `Highs` instance on every repetition.
- [ ] **Sample Size & Rigor:** $n = 10$ repetitions per `(pool_size, pruner_mode, solver_mode)` cell (report Median, IQR, Mean, p95, p99, and proven `mip_gap`).

## 3. Non-Goals & Safety Bounds
- **DO NOT** mix different `threads` settings across `Highs` instances within the same OS process (`ADR-002`, `HEUR-001`).
- **DO NOT** report `kTimeLimit` terminations as `OPTIMAL`; always inspect `getModelStatus()` and record `mip_gap`.
- **DO NOT** mutate `data/workout_library.csv` or `training_plans/`; write benchmark outputs to `data/experiments/EXP-003/`.

## 4. Control vs. Treatment Matrix & Test Corpus
- **Workload / Dataset:** Canonical workout library (`data/workout_library.csv` via `triplan.library.loader.load_candidates`) across pool sizes $N \in \{40, 80, 160, 324\}$ plus a deterministic synthetic $N = 500$ jittered pool (duration $\pm 10\%$, zone minutes re-normalized, seed 42) at `target_weekly_tss = 500.0`.
- **Condition 1 (Control A — Unpruned Full Pool Single Solve):** Unified `WeekModel` single solve (`threads=4`) across unpruned candidate subsets $N \in \{40, 80, 160, 324, 500\}$.
- **Condition 2 (Control B — 15-Seed $\times$ 2-Thread Portfolio Race, `EXP-001` Retest):** 15 worker processes $\times$ 2 threads (`4.0s` per-worker timeout) vs single deterministic solve at equal wall-clock and CPU budget on $N = 324$ and $N = 500$.
- **Condition 3 (Treatment A — Unified `WeekModel` + Pre-Filter & Stratified Dominance Pruning):** `filter_athlete_feasible_candidates` + `prune_8020_candidates` + `prune_dominated_candidates` (`src/triplan/solver/pruning.py`) + sparse `r_tot` run-share linearization (`ADR-029`) + Top-5 `cut_mode="selection"` (`ADR-018`).

## 5. Telemetry Instruments & Sampling Commands

- **Measurement Commands:**
