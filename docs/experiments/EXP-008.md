# `EXP-008`: Per-Sport Library Gap Audit Against Solver Demand

## 1. Objective & Pre-Registered Hypothesis
- **Objective:** Owner request: "evaluate each sport to see if we need more workouts beyond the 80/20 library and build them to help the solver." Audit Swim / Bike / Run / Strength / Brick duration x intensity-class coverage against what `CURRENT_ATHLETE` (45 / 60 / 75 min day caps, no pool, 24-week re-entry, run CTL < 15) and the reference long-course profile need; author what the audit justifies.
- **Null Hypothesis ($H_0$):** Adding authored rows leaves relaxations, single-run weeks and solved-vs-target unchanged, or breaks a Tier-0 / 80/20 check.
- **Alternative Hypothesis ($H_1$):** Fewer Tier-1 relaxations and fewer single-run weeks on `CURRENT_ATHLETE`, 0 fallback and 0 violations in all 8 seasons, and no grey-zone (`0 < q_i < 5`) session added.

## 2. Pre-Flight Ceteris-Paribus Hygiene Checklist
- [x] **Environment Quiescence:** matrix runs were started alone (8 processes, 3.5 s/week); single-season A/B runs ran 3-8 at a time and are used only for relative comparison.
- [x] **Cold vs. Warm State Control:** one process per season, deterministic solve per week (`ADR-018`); the control library is the pre-migration CSV, loaded with `load_candidates(path=...)`.
- [ ] **Sample Size:** n = 1 per cell; wall times are indicative (the 3.5 s HiGHS limit makes tail weeks time-dependent).

## 3. Non-Goals & Safety Bounds
- No guardrail threshold moved; every new row is derived with the shared formulas and passes the Tier-0 rows unchanged (0 violations).
- No Brick, no walk-jog rows (Findings 5, 6), no test workouts, no change to anchors, `control/*`, `solver/*` or the profile.

## 4. Control vs. Treatment Matrix & Test Corpus
- **Workload:** `python -m triplan.perf.season_validation` (4 distances x `current` / `reference`), per-season pick counts (scratch), and ablations that re-solve recorded `WeekRecord`s (`cfg` + `carry`) with one change.
- **Control:** master e10dcd4 library (38 `lib_default` rows). **Treatment:** + `scripts/migrations/m2026_11_16_library_gap_fill.py` (14 rows; `library/build.py::GAP_ENDURANCE_SPECS`, `GAP_STRENGTH_SPECS`, `gap_fill_rows`).
- **Framing finding:** `build_default_candidate_library()` is `load_candidates(library="default")`, so the solver never sees the ~480 80/20 scrape rows, only 38 hand-picked ones. The audit is of those 38.

## 8. Architectural Conclusion & Action Taken
**Verdict: H1 holds (`COMPLETE_ADOPTED`), with the costs in Finding 9.**

1. **The solver sees 38 rows, not the 80/20 library.** Flipping scrape rows to `lib_default` would not survive `refresh_from_8020_scrape`, so gaps are filled with `agent_authored` rows (`needs_review`).
2. **Run: short easy runs were the binding gap.** The shortest candidate was 30 min, so a re-entry week at run CTL < 15 could host one run before the ACWR / strain rows bound. Continuous Z1 runs of 15 and 20 min (`RUN_AE1_15/20`) and `RUN_AE1_STR25` (25 min, 6 x 20 s strides) replaced the 30 / 33 min runs in `CURRENT_ATHLETE` seasons; olympic single-run weeks 22 -> 9, max raw running ACWR 1.73 -> 1.57 (the in-model ACWR row is unchanged). 25 / 40 / 50 min easy runs, three tempo / threshold runs and a 45 min stride run were authored, measured and dropped: hard runs were never picked (run strain 75, re-entry) and the 25 / 40 min rows changed nothing for `CURRENT_ATHLETE`.
3. **Bike: hard sessions that double as stride sessions unblock the key-session minimum.** With 3 bike slots, `min_stride_sessions = 2` and `key >= 2` competed (week-26 ablation: `min_stride_sessions = 0` or bike frequency 2-4 removed the key slack). `BIKE_TH_STR_45` / `BIKE_TE_Z3_STR_45` (hard, 6 x 10 s seated cadence bursts as alactic Z5, `has_strides`) satisfy both and are the most-picked new rows after the runs. Also kept: 20 min spin, plain 45 min tempo / threshold rides, a 120 min trainer ride and a 120 min outdoor ride. A 45 min VO2 ride, 75 min tempo ride and 45 / 75 / 90 min easy rides were dropped (rarely or never picked).
4. **Strength: only a bodyweight prehab session (`STR_PREHAB_25`) was kept.** Two 35 min barbell maintenance lifts changed nothing the solver could not do already (identical relaxations) and doubled wall time through lift x cardio combos.
5. **Brick: do not add.** `safety_constraints.run_minutes` / `run_strain` count `sport == "Run"` and lift + run combos only, so a Brick's run leg bypasses the run-minute guard, running ACWR, run-share and weekly strain rows, while `calendar.make_allowed` counts it as a Bike and a Run session. A short brick would be a free run (`TASK-059`).
6. **Walk-jog: not representable.** One `mechanical_strain` / `neuromuscular_load` / `axial_load` per row and no walk component; a reduced impact load would be an invented number that loosens the ACWR / strain rows. Left to `TASK-058` on top of `TASK-023`. Continuous 15 min runs capture most of the ACWR effect.
7. **Swim (reference profile only):** 20 min technique, 40 min technique + aerobic and 65 min aerobic swims were added; a 45 min Z3 swim and a 40 min CSS swim were never picked and dropped. `CURRENT_ATHLETE` has no pool in re-entry; no dryland substitute was authored (no physiologically equivalent swim stimulus exists).
8. **No test workout added.** `RUN_CP_TEST` (70 min) cannot be hosted under the 45 min re-entry run ceiling, but `ADR-011` already locks tests out for 4-6 weeks and a shorter protocol would change the CP calibration contract; not a solver gap.
9. **Costs (honest):** (a) wall time, `CURRENT_ATHLETE` 32-34 s -> 42-51 s, reference 19-41 s -> 55-105 s (more candidates and combos). (b) Reference sprint / olympic / 70.3 base and build weeks now meet frequency, key and stride minimums that used to be relaxed, so their solved-above-target overshoot grew (sprint mean +121 -> +164, olympic +36 -> +75): the structure floor of `TASK-041` is exposed instead of hidden by relaxations. Reference Ironman week 21 undershoot grew (-52 -> -191; 48h caps, time-limited solve).
10. **Safety:** no bound relaxed; 0 fallback, 0 violations in 8 seasons; hard rows follow the library rule (>= 15 min Z3 or >= 5 min Z4+, `q_i >= 5`), every other row is 100% Z1/Z2 plus <= 2 min alactic seconds; `tests/test_library_gap_fill.py` asserts no grey-zone row.
